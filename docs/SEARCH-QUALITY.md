# Якість пошуку — 2026-10-03

## Що виміряли

Production `a2f5c64`, публічний HTTPS API, PostgreSQL, OpenAI `gpt-6-luna`,
114 опублікованих інновацій. Benchmark завершено о 20:47 Europe/Warsaw.
20 **синтетичних** описів польською; реальні звернення користувачів не читалися.
Очікувані ID визначено агентом **до** запуску. Це попередня розмітка, не
незалежна експертна оцінка й не репрезентативна оцінка всіх майбутніх звернень.

Метрика позитивного кейсу: чи є хоча б один наперед визначений прийнятний ID
серед максимум трьох результатів (Hit@3). Вона не вимірює якість кожної додаткової
пропозиції, фактичну доступність послуги або ефективність інновації.
Список очікуваних ID не є вичерпним переліком релевантних рішень.

| Група | Поточний production | Експеримент |
|---|---:|---:|
| Позитивні потреби, Hit@3 | 13/14 (92,9%) | 14/14 |
| Запити без підтвердженого рішення, no_match | 2/2 | 2/2 |
| Термінові звернення з потрібним контактом | 0/4 | Не тестувався |

Усі 14 позитивних кейсів production: semantic/openai/source_backed, без warnings.
У двох негативних і чотирьох термінових — keyword fallback через недостатню
семантичну відповідність; пожежа — template без AI-пояснення, решта — OpenAI.
Медіана повного POST matches із записом/читанням БД: **4,012 с**;
p95 за nearest rank: **5,569 с**, максимум **5,886 с** (20 послідовних запитів).
Це не навантажувальний тест. Експериментальна latency вимірює лише reranking,
тому напряму порівнювати її з HTTP baseline не можна.

## Підтверджені проблеми

1. **Немає скерування в термінових ситуаціях.** Відмова від інновації сама по
   собі не допомагає звернутися до служб. У пожежному кейсі питання
   «Dla kogo szukasz wsparcia…» недоречне. У 3/4 термінових кейсів додаються
   загальні матеріали про соціальні послуги, житло чи сектор опіки.
2. **Семантичний top-8 витісняє сильний лексичний результат.** Для loneliness-broad
   Senior CUDER: lexical rank 1, semantic rank 38, cosine 0,4536.
   Поріг 0,45 пройдений, але top-8 відсікає запис до AI. Просте зниження порога
   цю конкретну проблему не виправить. Це cosine, не «відсоток відповідності».
3. **Тематична схожість переважає явні обмеження.** Production запропонував
   взуття без бюджету на покупки та платформу для дорослих із синдромом Дауна
   на загальний запит про зустрічі seniorów. Обмеження зазначені, але результат
   усе одно займає місце в рекомендаціях.
4. **Related resources не проходять AI-перевірку релевантності.** Keyword fallback
   повертає загальні звіти навіть для автомобіля чи пожежі. Потрібна окрема
   перевірка цієї гілки, включно з запереченнями «не стосується соціальної допомоги».

## Перевірений напрям тюнінгу

Окремий shadow-експеримент, **не зміна application code або production**:
6 семантичних кандидатів + до 2 додаткових лексичних без повторів;
інструкція reranking відхиляє чужу цільову групу й явні ресурсні суперечності,
дозволяє корисний частковий інструмент для широкої потреби без обіцянок результату.
Використані збережені семантичні ранги; AI викликався наживо через штатний provider
з обліком usage/квот. Термінове скерування, related resources й UI не змінювалися.

На тих самих 16 нетермінових кейсах: 14/14 позитивних, 2/2 негативних.
Senior CUDER повернувся як partial із чесними обмеженнями; взуття прибрано;
бібліотечний кейс більше не містить загального музейного рішення.
Два параметри змінено разом, тож окремий внесок prompt/retrieval не виміряний.
Повторів і незалежного holdout ще немає. Це результат розробки, а не доказ
100% якості або стабільності. Перед перенесенням: нові кейси, повтори слабких
запитів, ablation prompt/retrieval і оцінка кожної пропозиції експертом.

## Служби та контакти

Додавати варто як **окреме скерування до допомоги**, з доступом до контактів
до заповнення/підтвердження форми та без очікування AI. Для явного термінового
звернення — окрема відповідь, без списку інновацій і відволікаючих матеріалів.
Номери й тексти — перевірений каталог з датою перевірки та джерелом, не генерація LLM.
Самостійна кнопка «Potrzebuję pilnej pomocy» потрібна навіть за помилки класифікації.
Автоматичний аналіз — додатковий механізм; не вважати простий keyword regex
надійним тріажем. Окремо тестувати профілактику, історичні події, заперечення,
навчальні приклади, евфемізми та різні мови.

Перевірено 2026-10-03:

- **112** — термінова допомога поліції, пожежної служби або медичної служби:
  [офіційні правила MSWiA](https://www.gov.pl/web/numer-alarmowy-112/co-zglaszac).
- **999** — екстрена медична допомога; альтернативно 112:
  [Pacjent.gov.pl](https://pacjent.gov.pl/na-ratunek).

Польський текст пропонованої картки: «Jeśli zagrożone jest życie lub zdrowie,
dzwoń teraz pod 112. W nagłym zagrożeniu medycznym możesz zadzwonić pod 999.
Ta aplikacja nie wzywa służb ratunkowych». Кнопки `tel:112` і `tel:999`.
Нетерміновим справам потрібні офіційні місцеві контакти, відібрані за громадою;
112 не використовувати як універсальну довідкову лінію. Номери конкретних
відділків/установ у цьому тесті не збиралися й не перевірялися.

## Відтворення та докази

- `tests/search-quality/cases.json`: попередня синтетична розмітка.
- `baseline-2026-10-03.json`: повні синтетичні API-відповіді, hash каталогу,
  час і модель; випадкові need IDs стосуються вже видалених тестових записів.
- `retrieval-2026-10-03.json`: ранги lexical/semantic для 14 позитивних кейсів.
- `experiment-2026-10-03.json`: кандидати, нова інструкція й відповіді варіанта.
- `scripts/evaluate-search.mjs`: opt-in `SEARCH_QA=synthetic`, справжній API,
  до 20 пошуків в одній сесії. Потрібні штатні серверні env; не переносити ключі
  на клієнт. Запускати лише на дозволеному середовищі. Може витрачати AI-квоту.
- `scripts/diagnose-search.ts`, `scripts/experiment-search.ts`: запуск через
  `tsx --conditions=react-server` або esbuild bundle із `--conditions=react-server
  --external:postgres --platform=node --format=esm`. Експеримент використовує
  зафіксовані ранги саме цього corpus snapshot; після змін спочатку оновити їх.

Production baseline видалив тільки свої синтетичні needs і персональні counters;
cleanup PASS. Спільний каталог, чужі справи та staff не змінювалися. Фактичний
AI usage і глобальні квоти збережені. Скрипти не друкують описи потреб чи ключі.
Файли доказів містять лише створені для benchmark синтетичні результати.

Наступна черга: термінове скерування → hybrid/reranker з holdout-перевіркою →
релевантність матеріалів → експертна розмітка реалістичних звернень.
