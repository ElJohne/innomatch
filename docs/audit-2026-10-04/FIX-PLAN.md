# Функціональні доробки — 2026-10-04

Запит власника: доробити M1–M7 швидко, без презентацій і довгих тестів.
План реалізації нижче виконано в межах цієї ітерації; фактичний результат,
перевірки та залишки — [FIX-RESULTS](FIX-RESULTS.md).

| Модуль | Ціль цієї ітерації | Критерій приймання |
|---|---|---|
| M1 | Розділити збій/no-match; інвалідувати кеш за каталогом/моделлю; показувати релевантні матеріали незалежно від інновацій | При збої є retry без неправдивого no-match; нове джерело оновлює старий пошук |
| M2 | Матеріали, тематичні фільтри й дані повітів у наявному каталозі; однаковий пошук UI/API | З каталогу доступні звіти/освіта/регіональні джерела; той самий запит дає той самий набір |
| M3 | Безпечна назва з опису, додаткові поля офіційної чернетки й обмеження фаз | `Np.`/`1.` не блокують ідею; сервер відхиляє неможливі строки; поля зберігаються |
| M4 | Повні черги модерації та лічильники | Понад 200 записів доступні сторінками; кількість відгуків не обрізається до 50 |
| M5 | Пагінація/непрочитані; прозоре передавання наступних змін ідеї/гранту | Старі звернення доступні, нова правка створює подію без витоку приватного тексту |
| M6 | ORGANIZER для знань, коректний pending після імпорту, зручний перегляд потреб індексації | Імпорт не перезаписує редакторські записи, інвалідує старий індекс і показує потребу оновлення |
| M7 | Редагування умов із revision; безпечний шлях відновлення після зміни джерела | Власник змінює умови; shared snapshot залишається незмінним; приховані джерела не розкриваються |

Перевірки: TypeScript, lint, швидкі unit/regression, короткі локальні HTTP smoke.
Повний E2E, build і PostgreSQL integration не запускаємо в цій швидкій ітерації,
відповідно до останнього запиту власника. Production/спільна БД не змінюються.
