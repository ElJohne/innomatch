Тому M2 можна демонструвати як частково реалізований модуль, але не як завершений регіональний портал знань.

Це аудит коду й наявного корпусу. У цьому підзавданні не змінено application code, БД, production чи конфігурацію. Основні suites запускає координатор аудиту; їхні результати не дублюються й не передбачаються тут. Історичні PASS у STATUS не зараховані як свіжий тест.

- Застосунок не має доказу переваги над усіма конкурентами. Порівняльну оцінку потрібно робити на однакових завданнях і джерелах, а не за кількістю сторінок.

## Знахідки та пріоритети

### F1 — P1: API й UI дають різні результати пошуку

Для `seniorzy bankomat` локальний corpus, застосований до точних предикатів із коду, дає UI **Merkury**, API **0**. **Підтверджено production read-only:** `/innowacje?q=seniorzy%20bankomat` — HTTP 200, HTML містить Merkury; `/api/innovations?q=seniorzy%20bankomat` — HTTP 200, `total: 0`; точне `q=Merkury` — `total: 1`. Причина: UI вимагає всі слова в різних частинах тексту й допускає довгі словоформи; API вимагає один безперервний substring. API також не шукає requirements/evidenceExcerpt, які враховує сторінка. Це зламає очікування інтеграцій і майбутнього client search, хоча поточний server-rendered каталог може працювати добре.

Приймання: UI й API мають однакові ID/order/total для `seniorzy bankomat`, `bankomatu seniorów`, точного `Merkury`, фільтрів та empty state; pagination не дублює й не пропускає записи.

### F2 — P1: основні частини знань важко знайти без грантової чернетки

Публічний відвідувач не має самостійного шляху до всіх звітів/освітніх ресурсів. Регіональні дані «заховані» за створенням власної ідеї. Видалення `/wiedza` було свідомим; пропозиція — компактний видимий розділ матеріалів у каталозі, узгоджений із поточною простою навігацією.

Приймання: із головної/каталогу без записувальних дій можна знайти навчальний матеріал, звіт про обрану тему, обрати повіт, побачити рік та відкрити первинне джерело. Клавіатура, 320px, 200% текст і contrast режими працюють.

### F3 — P1 для ROPS: аналітика змішує походження потреб

UI чесно попереджає про QA, але саму проблему не усуває. Без поля походження та виключення власних synthetic QA кількість звернень не придатна для операційних висновків. Зростання лічильника не є трендом суспільної проблеми. До показу керівництву потрібні фільтр test/live, погоджені категорії та достатня вибірка.

Приймання: synthetic needs не входять до стандартного production report; ADMIN може обрати test-inclusive view; B/EXPERT/anonymous не отримують ані counts, ані приватних полів. Для малих вибірок не робляться висновки про населення.

### F4 — P2: доказовість і актуальність корпусу обмежені

114 source-backed записів не дорівнюють 114 перевіреним успішним пілотам. 17 knowledge records — лише каталогові посилання; 0 CASE. Роки регіональних даних різні. Потрібна редакційна програма: джерело стадії, умови/вартість впровадження, контекст пілоту, точні фрагменти звітів, timestamp review та перевірка доступності посилань. Невідомі відомості залишаються невідомими.

Приймання: спочатку 10 найважливіших інновацій вручну прийняті ROPS; кожне твердження про tested має конкретне джерело; звіт показує область/рік/сторінку; зламане джерело видно редактору й не подається як надійний доказ.

### F5 — P2: масштабування й цикл оновлення

Публічний repository читає всі записи, UI відображає весь результат, а статичні показники оновлюються лише з release. Для 114 записів це прийнятна MVP межа; зі зростанням бібліотеки потрібні SQL filtering/pagination та operator freshness dashboard. Ручні каталожні зміни захищені від перезапису sync, але згодом потрібен керований спосіб прийняти новішу зовнішню версію.

4. Додати provenance потреб і відокремити QA в аналітиці; визначити зміст тематичних трендів із ROPS.
5. Упровадити review/freshness queue, контроль broken links, оновлення indicators і джерельних snapshot без ручного редагування коду.
6. Виміряти конкурентну перевагу: на однакових 10 задачах порівняти час пошуку джерела, кількість зайвих кроків, правильність території/року та наявність перевіреного evidence. Перемога має підтверджуватися цим benchmark, а не обіцянкою «кращі за всіх».

**Готовність:** джерельний каталог — придатний до демонстрації після актуального QA; повний Zasobnik wiedzy — частково готовий; операційна регіональна аналітика — потребує відділення synthetic data та редакційного приймання. Пропоновані поліпшення не виконувалися в межах аудиту.
