# Виправлення M4 / M5 — 04.10.2026

Реалізовано локально, без deployment, міграцій або production-записів.

- Скринька координатора `/admin` тепер має справжню серверну пагінацію по 50 розмов, фільтр непрочитаних і лічильник непрочитаних повідомлень по всіх доступних розмовах. Старі записи за межею 200 доступні через наступні сторінки.
- Додано `/wiadomosci` для повного списку власних розмов, із пагінацією і фільтром непрочитаних. Staff скеровується до `/admin`. Owner-фільтр збережено на сервері. Посилання з «Moje sprawy» інтегрує головний агент.
- `GET /api/threads` і `GET /api/admin/threads` приймають `page` та `unread=0|1`, повертають `items`, `total`, `unreadMessages`, `page`, `pageSize`, `hasNext`. Неправильні параметри API відхиляються валідацією. Існуючий сервіс listThreads лишив типовий ліміт 200 для старих споживачів; необмежений доступ забезпечують нові сторінки черги.
- `/admin/opinie` має фільтри всіх статусів і сторінки по 50 записів. Загальна кількість очікуваних відгуків обчислюється по всій таблиці, незалежно від обраної сторінки/статусу.
- Публічні відгуки на сторінці інновації показують справжній total, мають переходи до старших/новіших відгуків і відкривають розділ при переході на старші сторінки. API `GET /api/innovations/:id/feedback?page=N` повертає повну метаінформацію сторінки.
- Публічний total використовує ті самі PUBLISHED/sourceVersion/origin умови, що й список. Приватні, застарілі та недозволені synthetic відгуки не додаються до лічильника. Власники відгуків у public DTO відсутні.
- SQL сортує за updated_at та id для стабільного порядку при однакових timestamps. Це offset pagination: при одночасних нових повідомленнях порядок може зміститися; оновлення повертає актуальну чергу.
