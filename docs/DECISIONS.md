# Рішення

2026-10-03, агрегована аналітика:
- ADMIN-only звіт без додаткового AI: реальні підрахунки записів за 7/30/90 днів UTC,
  включно з неповним поточним днем. Не оцінка поширеності проблем серед населення.
- Дозволені назви груп спільні з формою потреби. Нестандартні значення — «Inne grupy»;
  назви гмін не виводимо, лише заповненість поля. Сирий приватний текст не йде в DTO.
- Статуси пошуку показують наявний записаний результат, навіть якщо старий каталог
  уже змінився; це явно пояснено в UI, без твердження про успішність впровадження.
- Не приписуємо старим потребам невідоме походження: PostgreSQL UI попереджає про
  можливість демонстраційних спроб у вибірці. Fixtures мають явну demo-позначку.
- Без нової міграції; SQL агрегує за один snapshot statement. Для великої БД потрібна
  окрема оцінка query plan/index за created_at; навантаження зараз не перевірене.

2026-10-03, M4:
- Одна заявка інтересу на owner/innovation; створює або використовує розмову про
  інновацію. Статус REQUESTED не означає прийняття учасника чи завершений пілот.
- Окремий відгук: оцінка, текст, покращення та основа думки. USED — самодекларація.
  Публікація тільки ADMIN після перевірки; зміна змісту скидає її на IN_REVIEW.
- Версія джерела прив'язана до відгуку: зміна/приховування інновації прибирає його
  з публічного списку. Повторна публікація потребує актуалізації автором.
- Походження визначає сервер. Fixture або синтетична інновація → SYNTHETIC;
  інші відгуки → USER_SUBMISSION. Публічний DTO не видає session/owner identifiers.
- PostgreSQL реалізація має transaction, unique constraints, row/advisory locks;
  runtime PostgreSQL перевірки не виконано. Автоматичні suites не запускались.

2026-10-03, M3:
- Загальна картка MI Connect, не копія офіційної Canwy. Social Innovation Canvas уже є
  у корпусі як опис і посилання; показуємо його за поточним статусом публікації.
  Початковий історичний запис про відсутність матеріалу більше не актуальний.
- AI preview → явне застосування у формі → окреме збереження. Жодного автоматичного
  submit, зміни stage або підміни авторської ідеї перевіреною інновацією ROPS.
- Подання створює одну приватну розмову та повідомлення; автор бачить згоду на доступ
  персоналу до поточної й майбутніх збережених редакцій. Draft не доступний staff API.
- Модель GrantCall має період, версію полів і джерело. Активних наборів/офіційної форми
  немає в наданому корпусі, тому генератор не реалізовано й M3 залишається PARTIAL.
- Локальний mock flow пройшов; live M3, PostgreSQL 0006, concurrency та cross-owner
  runtime перевірки не виконувались. Автоматичні suites не запускались за побажанням власника.

2026-10-03, M7 Middleman Innowacji:
- Структура плану взята зі SPEC §10.3; це чернетка послуги для установи, без вигаданих
  бюджетів, партнерів і гарантій. Джерельні фрагменти відокремлені від пропозицій.
- Власна потреба обов'язкова. Приватний owner API, номер revision, редагування без AI,
  копіювання зі джерелами й позначкою режиму. Зміна джерела закриває старий план.
- Передача персоналу лише через явне повідомлення з adaptationId; UI пояснює доступ
  до потреби, умов і майбутніх збережених редакцій. Персонал читає через дозволений Thread.
- Persistent reservation не тримає з'єднання БД під час виклику AI; ready повтори не
  генеруються знову. Після failed або 5-хв зависання можливий retry; exactly-once витрати
  після аварії між AI та записом не гарантуються. Ліміт 10 спроб/день на власника.
- Mock тільки за явної конфігурації. Немає fallback з live генерації до demo-плану.
- Локальний flow підтверджено; live AI M7, міграція 0005 та приймання партнерами не підтверджені.

2026-10-03, модерація та довготривалий доступ:
- Реалізовано локальний редактор M6 для ADMIN, статуси, джерела та підтвердження перевірки.
  Серверна версія запису захищає паралельні правки; імпорт не перезаписує ручну редакцію.
- При зміні запису старі пояснення приховуються, вектор видаляється, нова індексація явна.
- Гість має 90-денну сесію й приватний код із 256 біт випадковості; SHA-256 у сховищі.
  Код не засвідчує особу. Новий відкликає старий; вже відкриті сесії залишаються активними.
  Staff права окремі, до 8 годин; recovery ніколи їх не відновлює.
- Це інженерні рішення для вимог M5/M6, не погодження конкретного дизайну партнерами.
  Агрегована аналітика M6, M7, M3/M4 і матеріали подання залишаються наступними роботами.
- Автоматичні suites не запускались за побажанням власника. Локальна ручна перевірка
  модерації пройшла; PostgreSQL, live reindex та cross-browser recovery ще не перевірені.

2026-10-03, локальна ітерація персоналу/діалогів:
- ADMIN/EXPERT — підготовлені оператором accounts у PostgreSQL, salted scrypt через Node crypto,
  без нових залежностей. Гостьовий ownerId збережено; staff identity перевіряється за активністю,
  роллю й auth_version на кожному запиті. Пароль/роль змінює оператор CLI.
- Контекст розмови — власна потреба або опублікована інновація. Перед відправленням автор
  бачить повідомлення про передачу опису й обмежень персоналу; загального доступу до всіх потреб немає.
- Внутрішні сповіщення обчислюються з messages/read receipts без окремої таблиці notifications.
  Скринька та staff_read спільні для команди; email/push відсутні.
- Одна розмова на автора/контекст; перше повідомлення атомарне; відповіді idempotent;
  блокування рядка thread упорядковує конкурентні записи.
- M6 PARTIAL: staff auth та скринька є, модерація/редагування/аналітика ще відсутні.
- Поточна ітерація не змінювала production; 0003 і PostgreSQL integration очікують виконання.
